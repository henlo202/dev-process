# Test strategy

**What it is:** How the project proves that it meets its requirements: test
levels, tools, coverage targets, test data and what runs where.

## Contents
1. Test levels in use (unit, integration, end-to-end, contract, evals) and what each covers
2. Mapping rule: which kinds of requirement are proven at which level
3. Coverage targets for each tier (see the [QA guide](../guides/quality-assurance.md) for defaults)
4. Non-functional testing: performance, security, accessibility
5. Test data and environments
6. What runs locally, on each PR, nightly, and before release
7. Known manual checks, and why they cannot be automated
